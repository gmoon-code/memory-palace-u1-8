# AP Biology Expansion Pipeline

The application architecture is ready for all eight AP Biology units. Content is released one unit at a time so narrative speed never outruns scientific QA.

## Required pipeline for every future unit

### Stage 1 — Source inventory

Identify the classroom presentation/packet, current AP Biology Course and Exam Description scope, and Campbell Biology supporting sections. Confirm that the classroom source is complete before content generation begins.

### Stage 2 — Scientific atomization

Break every substantive source statement into atomic knowledge records. Preserve source wording and identify definitions, relationships, processes, equations, examples, skills, misconceptions, and teacher-specific additions.

### Stage 3 — AP scope mapping

Classify every atom as AP-required content/skill, teacher-required/supporting material, case study, course-meta material, or scope guard.

### Stage 4 — Conflict and misconception audit

Compare classroom material with the AP framework and Campbell support. Flag ambiguous wording, oversimplifications, outdated statements, and common misconceptions. Resolve these before mnemonic writing.

### Stage 5 — Canonical scientific lock

Create the versioned canonical catalog. Once locked, AI may vary narrative surface wording and practice phrasing but may not silently modify the scientific basis.

### Stage 6 — Memory Object design

Decide which records require exact-name retrieval, spelling, quantitative/application practice, confusable discrimination, or no mnemonic at all. Assign permanent palace loci only when a locus genuinely helps retrieval.

### Stage 7 — Narrative architecture

Design a coherent physical place, stable route, recurring guide/characters, causal story problem, and scientific interactions. Every scene must satisfy `NARRATIVE_SCENE_STANDARD.md`.

### Stage 8 — Student journey build

Generate the unit's guided journeys and short delayed-review targets. Application-only skills remain outside permanent palace scenes.

### Stage 9 — QA and release

Require complete record accounting, route coverage, exact-name introduction, source-language removal from student prose, scene-layout QA, scientific hash verification, API tests, and learner-flow testing.
