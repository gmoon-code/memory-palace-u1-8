# Content Studio Render Rehearsal

This branch prepares the first private Content Studio deployment rehearsal on Render while keeping the student GitHub Pages site unchanged.

## Rehearsal goals

- Deploy the FastAPI Content Studio runtime from the isolated admin branch.
- Keep publication and GitHub write delivery disabled.
- Run one authenticated owner session over HTTPS.
- Confirm persistent SQLite state survives a service restart or redeploy.
- Confirm the public student GitHub Pages artifact remains student-only.
- Preserve the current production `main` branch until the rehearsal passes.

## Render architecture

The root `render.yaml` defines a single Docker web service in the Singapore region. The service uses the production Content Studio Dockerfile and mounts one persistent disk at `/app/server_data`.

The persistent disk contains the admin session and audit database, Content Studio drafts and revisions, and publication metadata. Publication remains disabled during this rehearsal.

The service runs one instance. This is deliberate because the current Content Studio persistence layer uses local SQLite databases on a single attached disk.

Render terminates public TLS and forwards requests to the container. The container binds to the platform-provided `PORT` value and falls back to port 8000 for local use.

## Gates that remain closed

The rehearsal Blueprint deliberately sets these controls to false.

- `MEMORY_PALACE_ADMIN_PUBLICATION_ENABLED`
- `MEMORY_PALACE_GITHUB_PUBLICATION_ENABLED`
- `MEMORY_PALACE_GITHUB_ALLOW_MERGE`

No GitHub publication token is required or requested for this phase.

## Secrets

The Blueprint does not contain credentials. Render prompts for the owner username and password hash during initial Blueprint creation. The session secret is generated by Render.

Generate a password hash locally with

```bash
python scripts/generate_admin_credentials.py
```

Use only the generated password hash value for `MEMORY_PALACE_ADMIN_PASSWORD_HASH`. Keep the plaintext password outside the repository. The generated session secret from that helper is not needed when Render creates `MEMORY_PALACE_ADMIN_SESSION_SECRET` automatically.

## First live smoke test

After Render reports the service healthy, run

```bash
CONTENT_STUDIO_URL="https://<render-service>.onrender.com" \
CONTENT_STUDIO_USERNAME="<owner username>" \
CONTENT_STUDIO_PASSWORD="<owner password>" \
python scripts/smoke_content_studio.py
```

The smoke test verifies health, owner login, session access, protected catalog access, the publication gate, CSRF-protected logout, and session revocation.

## Persistence rehearsal

After the authenticated smoke passes, create a harmless draft in Content Studio, record its identifier, restart or redeploy the Render service, sign in again, and verify the draft and audit history still exist. Do not enable publication during this test.

## Promotion rule

This rehearsal does not merge admin code into `main`. Promotion requires a successful live authenticated smoke test, successful persistence rehearsal, review of deployment logs, and one final branch comparison showing no student-content drift.
